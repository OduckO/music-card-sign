# 云崽本地 icqq 音卡签名

把歌曲信息交给已登录的 icqq 账号，生成可以转发的 QQ 音乐卡片。你可以用聊天指令、网页或 HTTP 接口调用；完全相同的请求会复用已保存的卡片。

签名账号负责生成卡片，接收指令的账号负责把卡片发回当前会话。这两个账号可以不同，例如用 icqq 签名，再用 OneBot v11 或 Milky 发卡。

- 初次使用：按下面的[安装步骤](#安装)操作。
- 日常管理：看[命令](#命令)和 [WebUI](#webui)。
- 写代码调用：看[接口文档](docs/api.md)。
- 接入自己的歌曲 API：看[扩展 ID 查询](docs/development.md#扩展-id-查询)，支持插件包和单文件 JS。

## 安装

需要 TRSS-Yunzai、Git、Node.js 24、pnpm 9，以及通过 ICQQ-Plugin 登录的账号。icqq 版本要求为 `@icqqjs/icqq 1.10.3`。[JiuLi](https://github.com/HL-z7/JiuLi) 也使用下列步骤。

还没安装云崽时，先完成官方文档中的[安装项目](https://yunzai-bot.com/get-started/install)和[接入平台](https://yunzai-bot.com/get-started/platform)。

### 1. 安装插件和依赖

在云崽根目录打开终端，也就是能看到 `package.json` 和 `plugins/` 的目录：

```sh
git clone -b lib https://github.com/OduckO/music-card-sign.git plugins/music-card-sign
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

日常使用安装 `lib` 分支，它包含编译好的 JS。`main` 分支供开发使用。若安装过旧音乐签名脚本，请先停用，避免重复命令或端口冲突。

### 2. 重启云崽

已运行的云崽可由主人发送 `#重启`。首次启动可在根目录执行 `node .`；使用 PM2 时可执行 `pnpm run restart`。其他方式见[云崽项目命令](https://yunzai-bot.com/get-started/command)。

插件会生成 `config/music-card-sign.yaml`，保存你的设置。

### 3. 选择账号并测试

用主人账号给机器人发送：

```text
#音乐签名状态
#设置音乐签名Bot <QQ号>
#音之测测
```

只有一个 icqq 账号在线时，可以省略设置 Bot。默认测试歌曲是《晴天》；收到卡片和“音之测测通过”就表示生成与发送成功。

指定的签名账号离线时，插件会用框架列表中第一个在线 icqq 账号代签，并在日志里列出两个 QQ 号。原账号重新上线后，下次签名会用回原号，不需要改设置。

当前会话支持 ICQQ、OneBot v11、Milky。Milky 协议端需要支持 1.2 的 `light_app` 消息段。

发给自己收不到回传时，可设置一个能与签名账号私聊的联系人：

```text
#设置音乐签名联系人 <联系人QQ号>
#音之测测
```

联系人会收到真实的分享消息，无需回复。发送 `#设置音乐签名联系人 自己` 可恢复发给 Bot 自己。

## 命令

帮助对所有用户开放，其他命令需要主人身份。非主人使用其他命令时只记日志，不回复权限提示。[Bot 名单](#聊天指令响应名单)还可以限制哪些账号响应命令。

| 命令                                      | 用途                                                   |
| ----------------------------------------- | ------------------------------------------------------ |
| `#音乐签名帮助` / `#音乐签名`             | 查看帮助                                               |
| `#音乐签名状态`                           | 查看服务和配置图片，API Key 只显示是否已设置           |
| `#设置音乐签名Bot <QQ号>`                 | 指定签名账号；填 `自动` 或 `清除` 恢复自动选择         |
| `#设置音乐签名联系人 <QQ号>`              | 指定接收联系人；填 `自己` 或 `清除` 恢复发给自己       |
| `#设置音乐签名平台 <平台名>`              | 设置默认平台，如 `default`、`netease`、`kugou_concept` |
| `#设置音乐签名超时 <秒>`                  | 设置等待时间，支持小数，例如 `12.5`                    |
| `#开启音乐签名服务` / `#关闭音乐签名服务` | 开关服务并保存设置                                     |
| `#音之测测`                               | 用测试歌曲重新签名并发卡，不使用旧缓存                 |
| `#音之测测 {请求JSON}`                    | 临时测试另一首歌，不改默认测试歌曲                     |
| `#签名音卡 {请求JSON}`                    | 签名并发卡，优先使用缓存                               |
| `#音乐签名更新`                           | 更新插件                                               |
| `#音乐签名强制更新`                       | 丢弃插件中已跟踪文件的本地修改后更新                   |
| `#音乐签名更新日志`                       | 查看提交记录                                           |

`Bot` 不区分大小写，也可写作 `账号`。`音之测测` 可以省略开头的 `#`。设置成功后显示配置图片，图片生成失败时改用文字。

超时在命令、锅巴和 WebUI 中按秒填写，配置文件按毫秒保存。例如输入 `12.5`，文件中的 `timeoutMs` 为 `12500`。允许范围是 0.001～2147483.647 秒。

## WebUI

登录 QQBot-Web-Adapter 后，在扩展页面打开「音乐签名」；锅巴 next 则在自定义页面中打开。安装 `lib` 分支并重启后即可使用，无需自己编译网页。普通 Guoba-Plugin 使用[锅巴配置](#锅巴配置)表单。

工作台有两个页内标签：

- **服务设置**：设置账号、联系人、平台、超时、接口和测试歌曲。
- **请求音卡**：提交歌曲 JSON，可载入测试歌曲、强制重新签名，并查看或复制结果。

签名 Bot 可选在线 icqq 账号；接收联系人可选该账号的好友，两项也支持手填。账号留空时自动选择唯一在线 icqq 账号，联系人留空时发给签名 Bot 自己。

自定义平台和测试歌曲按字段填写，下方显示 JSON。必填项会提示，选填项留空不写入 JSON：

| 内容       | 必填                               | 选填                       |
| ---------- | ---------------------------------- | -------------------------- |
| 自定义平台 | 平台名称、`appid`（正整数）        | `appname`、`appsign`       |
| 歌曲信息   | `title`（歌名）、`url`（跳转链接） | `singer`、`audio`、`image` |
| 歌曲 ID    | `type`（查询来源）、`id`           | `_platform`（签名平台）    |

平台名称保存为小写，可添加多组。歌曲也可指定签名平台；留在自动识别时不生成 `_platform`。已有的内联平台和额外扩展字段会保留，切换歌曲填写方式后只提交当前模式的歌曲字段。

保存只提交改过的设置，成功后读取最新配置。切换标签也会刷新配置，但保留未保存的草稿。请求超时会停止等待，恢复按钮，不自动重试。

API Key 替换框留空会保留原值，勾选清除才删除。网页使用面板自身的登录权限，API Key 用于外部接口；直接打开本地 HTML 无法操作服务。

### 聊天指令响应名单

从在线 Bot 列表中选择账号，列表包含各协议的 Bot。黑、白名单分别保存，切换模式不会清空它们。

| 模式             | 哪些 Bot 响应本插件的聊天指令 |
| ---------------- | ----------------------------- |
| 关闭限制（默认） | 所有 Bot，仍检查主人权限      |
| 黑名单           | 名单之外的 Bot；空名单不限制  |
| 白名单           | 只有名单里的 Bot              |

**白名单为空时，所有 Bot 都不响应，包括帮助、设置和更新。** 请到锅巴或 WebUI 添加允许的 Bot，或切回「关闭限制」。静默时日志会说明原因和恢复方法。

名单只控制聊天响应，不影响签名账号、HTTP、Handler 和网页请求。因此签名 Bot 即使被禁止回复，仍能为其他 Bot 签名。

## HTTP 调用

默认使用云崽的 HTTP 服务，向以下地址发送 JSON POST：

```text
http://127.0.0.1:<云崽端口>/music_card/card
```

示例请求：

```json
{
  "type": "custom",
  "title": "晴天",
  "singer": "周杰伦",
  "url": "https://music.163.com/#/song?id=186016",
  "audio": "https://music.163.com/song/media/outer/url?id=186016.mp3",
  "_platform": "default"
}
```

`title` 和 `url` 必填，`audio` 可空。没有音频时可生成图文卡。有歌曲 ID 时也能查询后签名，具体格式见[接口文档](docs/api.md)。

成功时直接返回卡片 JSON，失败时返回带 `error` 的 JSON。GET 同一地址可查询状态，不会生成卡片。宿主和插件设有鉴权时，需带上对应凭据，见[请求鉴权](docs/api.md#请求鉴权)。

需要独立本地端口时，将 `localPort` 设为 `4567` 并重启，即可使用 `http://127.0.0.1:4567/music_card/card`。它只监听本机，云崽原有路由仍保留。

## 配置

推荐在锅巴或 WebUI 修改，保存后立即生效。手动编辑云崽根目录的 `config/music-card-sign.yaml` 后需重启。默认配置在插件的 `resources/config/config.yaml`。

| 字段              | 默认值             | 说明                                                                 |
| ----------------- | ------------------ | -------------------------------------------------------------------- |
| `enabled`         | `true`             | 是否启用服务                                                         |
| `botId`           | `""`               | 签名账号；空值自动选择唯一在线 icqq 账号                             |
| `targetId`        | `""`               | 联系人 QQ 字符串；空值发给自己                                       |
| `defaultPlatform` | `default`          | 跳转链接无法识别时使用的平台                                         |
| `path`            | `/music_card/card` | 签名接口路径                                                         |
| `timeoutMs`       | `15000`            | 等待上限，单位毫秒；查询、回传和会话发送分阶段计时，排队计入回传等待 |
| `localPort`       | `0`                | `0` 只用云崽服务；非零增加本地端口                                   |
| `apiKey`          | `""`               | 外部接口密钥，可不设                                                 |
| `platforms`       | `{}`               | 自定义签名平台                                                       |
| `testMusic`       | 《晴天》的请求     | 默认测试歌曲                                                         |

签名平台依次按：请求指定的 `_platform`、标题末尾的历史平台标记、跳转链接、默认配置选择。只看跳转链接，不用音频或封面判断平台。内置平台、自定义应用的三个字段及旧标题格式见 [API 平台说明](docs/api.md#自定义平台)。

`default` 的 appid 是 `102021671`，包名和签名为空。已有配置不会强制切换，想使用它可发送 `#设置音乐签名平台 default`。旧内置平台 `txqq` 已移除，旧配置自动改为 `default`；用户自定义的同名平台保留。QQ 音乐 `qq` 仍保留。

旧 JS 版升级时，若用户 YAML 不存在，会迁移插件中的 `config/config/config.json`，保留原文件。已有 YAML 时使用 YAML。

### 锅巴配置

在 [Guoba-Plugin](https://gitee.com/guoba-yunzai/guoba-plugin) 的插件配置中选择「本地 icqq 音卡签名」。字段规则与 WebUI 相同。默认平台可选内置或已保存的平台，也能输入新名称，与下方自定义平台一起保存。

接收联系人可手填，也可从好友列表选择。切换签名账号后，先保存并重新打开配置，再选好友。锅巴 next 按账号筛选好友；普通锅巴旧版组件可能显示所有账号合并的好友列表。

普通锅巴的 JSON 结果在保存后更新；锅巴 next 自定义页面实时预览。保存失败会提示原因并恢复旧配置。

修改测试歌曲或聊天名单不会打断正在签名的请求。面板中修改服务、账号、联系人、路由、端口、鉴权、超时或平台会重建服务，取消当前等待。通过设置 Bot 指令修改账号只影响后续请求。

## 缓存

已签出的卡片保存在插件的 `data/music-card-cache/`，重启后仍可使用。只有签名账号、实际平台和完整请求都相同才会复用；JSON 键的顺序和排版不影响结果。

例如，省略 `audio`、填写 `audio: ""` 和填写 `audio: null` 是三种请求；歌名多一个空格、ID 从数字变成字符串、改变链接或扩展字段，也会分别缓存。

命中缓存会跳过查询与签名。换了联系人后，已有缓存仍可复用；要检查新联系人的回传，用 `#音之测测`。同样，歌曲 API 或播放地址变化后，可用 `#音之测测 {请求JSON}` 重新生成并更新缓存。

卡片先返回，缓存后台保存。保存失败只记日志，不影响本次已生成的卡片；损坏的记录会重新签名。删除对应缓存文件可重签一项，清空缓存目录可重签全部。

## 更新

主人发送 `#音乐签名更新`，由云崽更新器处理拉取、依赖和重启。也可在云崽根目录执行，再重启：

```sh
git -C plugins/music-card-sign pull
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

更新沿用当前分支，通常是 `lib`。强制更新会覆盖已跟踪文件的本地修改；配置和缓存不在 Git 跟踪范围内，应继续保留。解压安装的副本需下载新版 `lib` 文件替换，不能直接 Git 更新。

## 常见问题

| 现象                                   | 先检查什么                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------ |
| 指令没反应                             | 日志中的 `[音卡指令]`：Bot 名单、主人身份、群聊回复条件                              |
| 插件没加载或缺依赖                     | 重新执行安装依赖命令；看最后一条“导入失败”或“应用 init”日志                          |
| 没有可用 icqq 账号                     | ICQQ-Plugin 是否已登录；多账号时是否指定签名 Bot                                     |
| 回传超时                               | 看日志中的签名 Bot 和接收 QQ；发给自己不通时改用联系人测试                           |
| 当前会话发送失败                       | 当前协议端是否支持卡片；测试结果中“签名/回传”和“发送回执”分别耗时多久                |
| HTTP 401                               | 宿主凭据及插件 API Key，见[鉴权](docs/api.md#请求鉴权)                               |
| HTTP 返回 HTML、Cloudflare 502/504/524 | 先在运行机器直连本地接口，再对照代理的端口、路径和日志                               |
| qsign 报 530                           | ICQQ-Plugin 使用的 qsign 服务是否正常                                                |
| QQ 分享权限错误 901208                 | 更换签名平台，可尝试 `_platform: "default"`                                          |
| 回包字段不匹配                         | 错误 JSON 的 `details.fields` 和 `request`，见[响应说明](docs/api.md#响应与状态查询) |
| 自定义 ID 查询失败                     | 提供查询的插件是否加载、来源名是否一致，见[接入检查](docs/development.md#接入检查)   |
| 本地端口被占用                         | 更换 `localPort`，或设为 `0`                                                         |
| 更新指令没反应                         | 尝试本体 `#更新music-card-sign`，更新后重启                                          |

日志的 `[音卡 HTTP]`、`[音卡签名]`、`[音卡发送]` 分别对应接口、生成与发卡。签名失败日志包含请求体，HTTP 日志包含状态和耗时。

本机测试用 `127.0.0.1`，其他电脑访问用服务器地址。本地正常、域名失败时重点检查反向代理。JiuLi 尚未启动完成时会返回 `503`，错误中包含启动阶段。
