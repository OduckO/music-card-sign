# 云崽本地 icqq 音卡签名

使用 TRSS-Yunzai 中已登录的 ICQQ-Plugin 账号生成音卡 JSON，供 HTTP 调用、云崽命令和其他插件使用。歌曲可以提交完整信息，也可以用 ID 查询；完全相同的请求复用已保存的音卡。

| 要做什么                                     | 阅读入口                                             |
| -------------------------------------------- | ---------------------------------------------------- |
| 安装插件并发出第一张音卡                     | [安装](#安装)                                        |
| 设置账号、平台或测试服务                     | [命令](#命令) · [配置](#配置)                        |
| 在浏览器中设置或请求音卡                     | [WebUI](#webui)                                      |
| 通过 HTTP 取得音卡 JSON                      | [接口文档](docs/api.md)                              |
| 在自己的云崽插件中调用音卡服务               | [Handler 接入](docs/development.md#handler-接入)     |
| 用自己的 API 根据歌曲 ID 查询信息            | [扩展 ID 查询](docs/development.md#扩展-id-查询)     |
| 在 `plugins/example/` 放一个 JS 文件提供查询 | [单文件 JS 插件](docs/development.md#单文件-js-插件) |

## 安装

需要已安装的 TRSS-Yunzai、Git、Node.js 24 和 pnpm 9。签名账号通过 ICQQ-Plugin 接入，icqq 版本要求为 `@icqqjs/icqq 1.10.3`。

使用 [JiuLi](https://github.com/HL-z7/JiuLi) 时，沿用下方安装步骤，签名账号同样通过 ICQQ-Plugin 接入。

尚未安装云崽时，先按云崽文档的 [安装项目](https://yunzai-bot.com/get-started/install) 和 [接入平台](https://yunzai-bot.com/get-started/platform) 完成框架安装与账号登录。以下步骤按 [插件包安装流程](https://yunzai-bot.com/get-started/plugins) 编写。

### 1. 安装插件和依赖

在云崽根目录打开终端，该目录下应能看到 `package.json` 和 `plugins/`。Windows 可在文件管理器中打开此目录，再选择“在终端中打开”。

```sh
git clone -b lib https://github.com/OduckO/music-card-sign.git plugins/music-card-sign
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

`lib` 分支是可直接加载的 JS 版本，`main` 分支用于 TS 开发。依赖安装限定在插件目录，`--ignore-workspace` 让 pnpm 使用插件自己的依赖配置。

如果已安装旧音乐签名脚本，先停用它，避免重复命令和端口冲突。

### 2. 启动或重启云崽

首次启动可在云崽根目录执行：

```sh
node .
```

已运行的云崽可由主人发送 `#重启`；使用 PM2 管理时，也可在云崽根目录执行 `pnpm run restart`。其他启动方式见 [云崽项目命令](https://yunzai-bot.com/get-started/command)。

插件首次加载会生成云崽根目录的 `config/music-card-sign.yaml`。

### 3. 选择账号并测试

以下指令在机器人会话中发送，需要主人权限。先查看状态；多个 icqq 账号在线时，再指定签名 Bot：

```text
#音乐签名状态
#设置音乐签名Bot <QQ号>
#音之测测
```

只有一个 icqq 账号在线时可省略设置 Bot 的步骤。`#音之测测` 默认使用《晴天》，每次重新签名，成功后发送到当前会话并报告耗时。收到音卡和“音之测测通过”即完成首次检查。

当前会话支持 ICQQ 和 OneBot v11。可以由 OneBot v11 账号接收指令，再由配置的 icqq 账号生成音卡，最后发回原会话。ICQQ 会话通过 SDK 发送原始 JSON，OneBot v11 使用其 JSON 消息格式。

测试分别报告签名/回传和当前会话发送回执的耗时。收到匹配的完整 JSON 就发往当前会话，开始通知回执和缓存落盘不阻塞转发；发送超过 `timeoutMs` 或文字通知失败时会记录日志。日常重复请求可用 `#签名音卡` 或 HTTP，命中缓存后跳过提交与回传。

签名时向自己或配置的联系人提交音乐分享，随后捕获匹配的音卡 JSON。本次内部回包不会交给 shareMusic 等插件再次解析，用户正常分享继续分发。

发给自己无法收到回传时，可指定一个能与签名账号私聊的联系人，再测试：

```text
#设置音乐签名联系人 <联系人QQ号>
#音之测测
```

该联系人会收到实际的音乐分享。插件捕获签名 Bot 发出的同步 JSON，联系人无需回复或转发。使用 `#设置音乐签名联系人 自己` 可恢复默认目标。

## 命令

帮助对所有用户开放，其他命令通过 `e.isMaster` 检查主人身份。非主人触发管理或发卡指令时，插件只记录日志，不发送权限提示。Bot 名单在权限检查之前生效，被排除的 Bot 连帮助也会静默忽略。

| 命令                                      | 用途                                                   |
| ----------------------------------------- | ------------------------------------------------------ |
| `#音乐签名帮助` / `#音乐签名`             | 查看常用指令、API 路径和文档入口                       |
| `#音乐签名状态`                           | 查看服务与当前配置图片，API Key 只显示是否设置         |
| `#设置音乐签名Bot <QQ号>`                 | 保存签名账号，立即用于后续请求                         |
| `#设置音乐签名Bot 自动`                   | 清除固定账号，恢复自动选择；也可填写 `清除`            |
| `#设置音乐签名联系人 <QQ号>`              | 保存音卡接收联系人，立即用于后续分享                   |
| `#设置音乐签名联系人 自己`                | 恢复发给签名 Bot 自己；也可填写 `清除`                 |
| `#设置音乐签名平台 <平台名>`              | 保存默认音卡平台，如 `default`、`netease` 或自定义名称 |
| `#设置音乐签名超时 <秒>`                  | 设置回传等待时间，支持小数，例如 `12.5`                |
| `#开启音乐签名服务` / `#关闭音乐签名服务` | 保存开关并挂载或卸载服务                               |
| `#音之测测`                               | 用配置中的 `testMusic` 重新签名，回传后发送音卡        |
| `#音之测测 {完整请求JSON}`                | 临时更换测试歌曲或平台，不修改默认测试配置             |
| `#签名音卡 {完整请求JSON}`                | 优先复用精确缓存，再发送音卡到当前会话                 |
| `#音乐签名更新`                           | 调用云崽更新器更新本插件                               |
| `#音乐签名强制更新`                       | 丢弃插件内已跟踪文件的本地修改后更新                   |
| `#音乐签名更新日志`                       | 查看本插件的 Git 提交日志                              |

`Bot` 大小写均可，设置账号也支持 `#设置音乐签名账号 <QQ号>`。`音之测测` 可省略开头的 `#`；失败时会提示生成/回传或当前会话发送阶段的原因。

超时指令、锅巴和 WebUI 均按秒填写，配置文件仍保存 `timeoutMs`（毫秒）；例如 `#设置音乐签名超时 12.5` 保存为 `12500`。输入范围为 0.001 到 2147483.647 秒。

帮助、状态和设置使用 ktr 图片；设置账号、联系人、平台、超时或服务开关成功后，也会显示当前配置图片。参数或保存错误立即回复文字，截图不可用时回到文字说明。图片渲染按需加载，临时 HTML 在截图结束后清理。

## WebUI

插件提供一个「音乐签名」工作台，服务设置与音卡请求在页内切换：

- **QQBot-Web-Adapter**：登录 Web 面板，在扩展页面菜单中打开。
- **锅巴 next**：登录面板，在自定义页面菜单中打开。普通 Guoba-Plugin 继续使用下文的表单配置。

安装 `lib` 分支后页面已编译，重启云崽及面板即可加载。两个面板共用 `webadapter/` 中的页面和同一份配置。

React 源码位于 `webadapter/src/`；运行 `pnpm run build:web` 后，页面、脚本、样式和字体输出到 `webadapter/`，由同一个 `index.js` 注册。`lib` 分支只发布编译产物。

服务设置包含签名账号、接收联系人、默认平台、超时、HTTP 路由、端口、API Key、自定义平台和测试歌曲。签名 Bot 列表只显示框架在线的 icqq 账号，选定账号后接收联系人列出该账号的好友；两项均可手填 QQ。清空账号恢复自动选择，多个账号在线时需指定一个；清空联系人恢复发给签名 Bot 自己。保存后立即生效；API Key 不会回传给页面，替换框留空保留原值，勾选清除才会删除。

「聊天指令响应」可选择名单模式，并从框架在线 Bot 中多选账号，列表显示昵称、Bot 号和适配器。这里包含各协议的 Bot；签名账号列表仍只提供 icqq。两份名单分别保存，切换模式不会清空。

| 模式             | 作用                                                              |
| ---------------- | ----------------------------------------------------------------- |
| 关闭限制（默认） | 所有 Bot 均可响应，仍按上述主人权限处理各指令                     |
| 黑名单           | 黑名单中的 Bot 静默忽略本插件全部聊天指令；空黑名单不限制任何 Bot |
| 白名单           | 只有白名单中的 Bot 可响应，其余 Bot 全部静默                      |

**特别注意：白名单模式下，名单为空会让所有 Bot 静默，包括帮助、设置与更新指令。** 此时请登录锅巴或 WebUI，在「聊天指令响应」中添加允许响应的 Bot，或将模式切回「关闭限制」，保存后恢复响应。每次静默拦截都会记录原因和恢复方法，不会发出聊天提示。

名单只控制接收指令的 Bot，不影响签名账号选择、HTTP、Handler 或面板请求音卡。即使签名 Bot 在黑名单中，或不在白名单中，其他允许响应的 Bot 仍能调用它签名。

自定义平台和测试歌曲逐项填写，下方实时生成 JSON，可直接复制。已有配置自动回填，留空的选填项不会写入 JSON：

- **自定义平台**：先填写用于引用的平台名称，再填写三个固定字段 `appid`、`appname`、`appsign`。仅 `appid` 必填，须为正整数；平台名称保存为小写，可以添加多组。
- **歌曲信息**：必填歌名 `title` 与跳转链接 `url`；歌手 `singer`、音频 `audio` 和封面 `image` 选填，自动生成 `type: "custom"`。
- **歌曲 ID**：必填查询来源 `type` 与歌曲 `id`，来源可以是其他插件注册的名称。
- **签名平台**：默认自动识别，不生成 `_platform`；选择平台后生成该字段。已有内联平台对象可以继续保留。

缺少必填项时会在对应输入框提示。编辑时保留已有的额外扩展字段；切换歌曲模式后只提交当前模式的歌曲字段。

切换到「请求音卡」提交歌曲 JSON，可载入测试歌曲、选择强制重新签名、查看并复制完整 JSON。成功结果包含歌名、歌手、应用 ID 和耗时；错误显示服务返回的原因。电脑上请求与结果并排，手机上依次排列。切换标签会保留未提交内容。

页面接口沿用所在面板的登录鉴权；插件的 `apiKey` 用于外部签名接口，两者独立。直接用浏览器打开本地 HTML 无法操作服务。

## HTTP 调用

默认复用云崽 HTTP 服务，签名地址为：

```text
http://127.0.0.1:<云崽端口>/music_card/card
```

向完整地址发送 JSON POST。成功响应直接是音卡 JSON 原文，可作为 JSON 消息发送。请求字段、自定义平台、ID 模式、鉴权和错误码见 [接口文档](docs/api.md)。

完整歌曲请求示例：

```json
{
  "type": "custom",
  "title": "晴天",
  "singer": "周杰伦",
  "url": "https://music.163.com/#/song?id=186016",
  "audio": "https://music.163.com/song/media/outer/url?id=186016.mp3",
  "_platform": "default"
}
```

直接提交歌曲信息时，`audio` 可省略、为空字符串或 `null`；填写时使用 HTTP(S) 音频地址。ID 查询的返回字段要求见 [扩展 ID 查询](docs/development.md#解析器参数与返回值)。

先用 GET 访问签名地址确认状态，再提交 POST；宿主有鉴权时需携带相应凭据。成功读取响应原文，失败检查 HTTP 状态及 JSON 的 `error`、`request`。请求解析、查询、提交和回传错误的格式见 [响应与状态查询](docs/api.md#响应与状态查询)。

需要单独的本地端口时，将配置中的 `localPort` 改为 `4567` 并重启，签名地址变为 `http://127.0.0.1:4567/music_card/card`。额外服务仅监听 `127.0.0.1`，宿主路由仍保留。

## 配置

用户配置在云崽根目录的 `config/music-card-sign.yaml`；默认配置在插件的 `resources/config/config.yaml`。手动修改用户配置后重启云崽，账号、联系人、默认平台和开关也可通过命令立即设置。

| 字段              | 默认值               | 用途                                                          |
| ----------------- | -------------------- | ------------------------------------------------------------- |
| `enabled`         | `true`               | 加载时是否启用服务                                            |
| `botId`           | `""`                 | 固定签名账号；留空时仅在一个 icqq 账号在线时自动选择          |
| `targetId`        | `""`                 | 音卡接收联系人 QQ 号，使用字符串；留空发给签名 Bot 自己       |
| `defaultPlatform` | `default`            | 跳转链接未识别时使用的平台；支持内置及自定义平台名称          |
| `path`            | `/music_card/card`   | 宿主及额外本地服务的签名路由                                  |
| `timeoutMs`       | `15000`              | 歌曲查询、JSON 回传及会话发送的超时，各阶段独立计时，单位毫秒 |
| `localPort`       | `0`                  | `0` 复用宿主；非零时额外启动本地端口                          |
| `apiKey`          | `""`                 | 可选插件鉴权，见 [请求鉴权](docs/api.md#请求鉴权)             |
| `platforms`       | `{}`                 | 自定义平台名称与应用信息的映射                                |
| `testMusic`       | 《晴天》的自定义请求 | `#音之测测` 默认歌曲，可替换完整歌曲字段并指定 `_platform`    |

从旧 JS 版升级时，若用户 YAML 尚不存在，会迁移插件中的 `config/config/config.json` 并保留旧文件；已有 YAML 时以 YAML 为准。

默认平台 `default` 使用 `appid: 102021671`，`appname` 和 `appsign` 均为空字符串。已有配置若保存了其他默认平台，更新后发送 `#设置音乐签名平台 default` 即可切换，也可在锅巴选择「默认应用」。

内置 QQ 本体平台 `txqq` 已移除，QQ 音乐 `qq` 保留。旧配置的 `defaultPlatform: txqq` 会在加载时自动改为 `default` 并保存；用户在 `platforms` 中自定义的同名平台保留。

平台按显式 `_platform`（兼容 `platform/source`）、标题中的历史平台标记、歌曲跳转链接、`defaultPlatform` 的顺序选择。例如跳转链接属于网易云时使用 `netease`，传入 `_platform: "default"` 可强制使用默认应用。仅识别 `url/jumpUrl` 等跳转字段的域名，音频 `audio` 和封面不参与识别；未识别到平台时使用默认配置。

酷狗概念版使用 `_platform: "kugou_concept"`（appid `101706348`），也可在锅巴选择或发送 `#设置音乐签名平台 kugou_concept` 设置默认平台。平台名单独传入，`title` 保留歌曲名。

兼容 shareMusic 的 `title: "歌名_平台名"` 写法，也支持 `歌名_*平台名`。仅匹配标题末尾完整的内置或自定义平台名，名称含下划线时优先匹配较长名称，匹配后移除这段后缀。例如 `晴_天_kugou_concept` 使用概念版签名，歌名保留为 `晴_天`；歌名内部的 `_` 和未匹配的平台后缀保留。

概念版官网域名 `kugouyouth.com` 可自动识别。普通 `kugou.com` 歌曲链接与音频 CDN 不足以区分两种应用，使用概念版时传入平台字段或标题标记。样本格式见[接口文档](docs/api.md#酷狗概念版链接样本)。

`type` 只选择 ID 查询来源。ID 请求未携带跳转地址时使用默认平台，可通过 `_platform` 指定音卡平台。

自定义 ID 查询可放在开发者自己的插件包中，也可放在 `plugins/example/` 的单个 JS 文件中。使用 `music.info.<来源名>` Handler 声明查询方法，或在 `init()` 调用 `registerMusicResolver()`；单文件也可以导入其他插件的查询函数。目录位置、两种接法和测试方法见 [扩展 ID 查询](docs/development.md#扩展-id-查询)。`platforms` 配置用于音卡应用信息。

### 锅巴配置

已安装 [Guoba-Plugin](https://gitee.com/guoba-yunzai/guoba-plugin) 时，在锅巴的插件配置中选择「本地 icqq 音卡签名」。可编辑上表全部设置；自定义平台和测试歌曲使用原生子表单，API Key 使用密码输入框。

在「自定义平台」中添加或编辑条目，填写平台名称与三个应用字段；在「测试歌曲」中选择填写方式，并填写该模式的必填项。字段规则与 WebUI 相同。普通锅巴下方的 JSON 为只读结果，保存后更新，可选中复制；锅巴 next 的「音乐签名」自定义页面提供实时预览和复制按钮。

默认签名平台点击后列出内置与已保存的自定义平台，可直接选择，也可输入新平台名称，与下方新增的平台一起保存。

签名 Bot 可从在线 icqq 账号中选择或手填 QQ。接收联系人可手填，也可用「从好友中选择联系人」单选后保存；选择结果会写入接收联系人 QQ。好友组件按已保存的签名 Bot 筛选，切换账号后先保存并重新打开配置，再选好友。锅巴 next 支持按账号筛选；普通锅巴的旧版好友组件可能显示框架合并的好友列表。

点击保存后写入同一份用户 YAML，并立即重新加载音卡服务。自定义平台只需 `appid`，`appname` 和 `appsign` / `app_sign` 可省略或为空；Bot 号留空恢复自动选择，接收联系人留空恢复发给自己。参数错误或新端口无法使用时，会提示失败并恢复旧配置和服务。

保存锅巴配置或切换默认平台、联系人会重建服务，取消当前等待中的签名请求；之后可重新提交。联系人只影响分享目标，缓存命中仍直接复用原音卡；检查新联系人的回传请用 `#音之测测`。切换实际平台后，缓存按新平台分别保存。

## 缓存

音卡长期保存在插件的 `data/music-card-cache/`，重启后可继续复用。命中要求签名账号、实际平台信息和完整请求字段全部相同，只忽略 JSON 对象键顺序和 JSON 文本排版。

签名成功后立即返回完整原文，缓存后台写入。落盘期间，相同请求可复用本次原卡；关闭或重载服务会等待写入完成，写入失败会记录日志。

以下差异会分别缓存，即使生成的音卡看起来相同：

| 请求差异             | 示例                                       |
| -------------------- | ------------------------------------------ |
| 字符串内部空白       | `title: "晴天"` 与 `title: "晴天 "`        |
| 字段是否存在         | 省略 `singer` 与 `singer: ""`              |
| 空音频的表示方式     | 省略 `audio`、`audio: ""` 与 `audio: null` |
| 值类型               | 数字 ID 与字符串 ID                        |
| 地址、平台或扩展信息 | URL 原文、数组顺序和未知字段不同           |

ID 请求命中后会跳过歌曲查询和分享提交。只保存匹配成功的回包，损坏记录会重新签；磁盘读写错误写入日志，保存失败时仍返回本次成功签出的音卡。

QQ 转存封面不改变缓存规则：输入的 `image` 地址不同会重新签名，原请求完全相同时复用保存的完整回包。

删除对应缓存文件可重新签该请求；清空缓存目录可重新签所有请求。也可使用 `#音之测测 {请求JSON}` 绕过旧缓存，成功后更新记录。

## 更新

主人可发送 `#音乐签名更新`，由云崽本体更新器处理 Git 拉取、依赖更新和重启。更新沿用安装分支，通常是 `lib`；`#音乐签名更新日志` 查看插件提交记录。

需要覆盖插件内已跟踪文件的本地修改时，使用 `#音乐签名强制更新`。用户配置和音卡缓存位于 Git 跟踪范围之外，更新后继续使用。

也可在云崽根目录手动执行，然后重启云崽：

```sh
git -C plugins/music-card-sign pull
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

升级时保留用户配置和 `data/music-card-cache/`。手动解压安装的副本无法直接用 Git 更新，可从仓库下载新的 `lib` 分支文件后替换运行文件。

## 常见问题

| 现象                     | 检查方法                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 加载时缺少依赖           | 在云崽根目录重新执行安装步骤中的 pnpm 命令                                                            |
| 找不到在线 icqq 账号     | 确认 ICQQ-Plugin 已接入且账号在线，检查配置的 Bot 号                                                  |
| 多账号时无法自动选择     | 用 `#设置音乐签名Bot <QQ号>`，或在请求中传入 `self_id`                                                |
| 回传超时                 | 发给自己无回传时设置接收联系人，再用 `#音之测测`；查看日志中的 Bot 和接收 QQ                          |
| 当前会话发送失败         | 检查接收会话的协议是否支持 JSON 卡片                                                                  |
| HTTP 401                 | 检查宿主鉴权及插件 `apiKey`，参见 [请求鉴权](docs/api.md#请求鉴权)                                    |
| 回包字段不匹配           | 查看错误响应的 `details.fields` 及 `request`；封面转存不会触发此错误                                  |
| HTTP 返回 HTML           | 更新插件并重启；新版签名失败通过 `503` 返回 JSON，检查日志中的实际响应状态                            |
| qsign 报 530             | 检查 ICQQ-Plugin 使用的 qsign 服务；这会导致音乐分享提交失败                                          |
| QQ 分享权限错误 901208   | 更换签名平台；强制使用默认应用可传 `_platform: "default"`，直接传入的 appid 会覆盖默认设置            |
| 自定义 ID 提示未注册来源 | 确认开发者插件已加载并注册，请求 `type` 与注册名完全一致；见 [接入检查](docs/development.md#接入检查) |
| Cloudflare 502/504/524   | 在运行机器上直接访问签名地址，对照 HTTP 入口及响应日志检查代理与服务                                  |
| 指令静默无响应           | 查看 `[音卡指令]` 的拦截原因；在锅巴或 WebUI 调整 Bot 名单或关闭限制，非主人只能使用帮助              |
| 测试指令无响应           | 查看是否有「应用 init 完成」及「音之测测开始」日志，并检查 Bot 名单、主人身份和群聊回复条件           |
| 更新指令无响应           | 先用本体 `#更新music-card-sign` 升级并重启；新版会记录转交及结束日志，未执行时提示                    |
| 本地端口被占用           | 修改 `localPort`，或设为 `0` 使用宿主服务                                                             |

日志按 `[音卡签名]`、`[音卡指令]`、`[音卡 HTTP]`、`[音卡发送]` 标识阶段，记录启动、账号选择、接收 QQ、缓存命中、提交分享、回传匹配和发送结果。签名失败日志附上请求体，HTTP 最后一条错误日志包含与响应一致的错误详情和请求；响应日志记录状态及耗时。

`#音之测测` 分别报告“签名/回传”和“当前会话发送回执”的耗时。完整回包匹配后立即返回，缓存在后台写入；排查转发速度时，先看耗时集中在哪一段。

应用加载日志先记录实际 `lib/apps/` 路径，再逐文件记录“开始导入”“导入完成”或“导入失败”及耗时。加载异常时，用最后一条导入日志定位文件；导入失败会同时记录原始错误。应用已导入完成时，继续查看“应用 init 开始”和“应用 init 完成”，确认服务初始化进度。

在运行机器上直接访问时使用 `127.0.0.1`；从其他电脑访问则使用服务器地址。直接 GET 正常、域名访问超时时，检查反向代理的目标端口和路径。JiuLi 尚未就绪的请求会返回 `503`，JSON 错误中保留启动阶段。

HTTP、Handler 和命令可以使用不同的生成账号与接收会话。其他插件接入 Handler 或扩展 ID 查询，见 [开发指南](docs/development.md)。
