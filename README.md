# 云崽本地 icqq 音卡签名

复用 TRSS-Yunzai 中已登录的 ICQQ-Plugin 账号，向账号自己提交音乐分享，捕获匹配的音卡 JSON 原文。可通过 HTTP、云崽命令或 Handler 取得音卡；完全相同的请求会复用已保存的结果。

[安装](#安装) · [命令](#命令) · [配置](#配置) · [接口文档](docs/api.md) · [开发指南](docs/development.md)

## 安装

需要已安装的 TRSS-Yunzai、Git、Node.js 24 和 pnpm 9。签名账号通过 ICQQ-Plugin 接入，icqq 版本要求为 `@icqqjs/icqq 1.10.3`。

使用 [JiuLi](https://github.com/HL-z7/JiuLi) 时，沿用下方插件安装步骤，签名账号同样需要 ICQQ-Plugin。插件兼容未提供 `addCleanup` 的宿主，并通过 JiuLi 的 `onUnload` 释放服务资源。

尚未安装云崽时，先按云崽文档的 [安装项目](https://yunzai-bot.com/get-started/install) 和 [接入平台](https://yunzai-bot.com/get-started/platform) 完成框架安装与账号登录。以下步骤按 [插件包安装流程](https://yunzai-bot.com/get-started/plugins) 编写。

### 1. 安装插件和依赖

在云崽根目录打开终端，该目录下应能看到 `package.json` 和 `plugins/`。Windows 可在文件管理器中打开此目录，再选择“在终端中打开”。

```sh
git clone -b lib https://github.com/OduckO/music-card-sign.git plugins/music-card-sign
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

`lib` 分支是可直接加载的 JS 版本，`main` 分支用于 TS 开发。依赖安装限定在插件目录，`--ignore-workspace` 让 pnpm 使用插件自己的依赖配置。

如果已安装旧音乐签名脚本，先停用它，避免重复命令和端口冲突。

### 2. 启动或重启云崽

首次启动可在云崽根目录执行：

```sh
node .
```

已运行的云崽可由主人发送 `#重启`；使用 PM2 管理时，也可在云崽根目录执行 `pnpm run restart`。其他启动方式见 [云崽项目命令](https://yunzai-bot.com/get-started/command)。

插件首次加载会生成云崽根目录的 `config/music-card-sign.yaml`。

### 3. 选择账号并测试

以下指令在机器人会话中发送，需要主人权限。先查看状态；多个 icqq 账号在线时，再指定签名 Bot：

```text
#音乐签名状态
#设置音乐签名Bot <QQ号>
#音之测测
```

只有一个 icqq 账号在线时可自动选择，省略设置 Bot 的步骤。`#音之测测` 默认使用《晴天》，进入后先回复测试开始，每次重新生成音卡，成功后发送到当前会话并报告耗时。当前会话支持 ICQQ 和 OneBot v11；签名仍使用在线 icqq 账号。

## 命令

所有命令均要求主人权限。

| 命令                                      | 用途                                            |
| ----------------------------------------- | ----------------------------------------------- |
| `#音乐签名状态`                           | 查看开关、签名账号、在线 icqq 和等待请求数      |
| `#设置音乐签名Bot <QQ号>`                 | 保存签名账号，立即用于后续请求                  |
| `#设置音乐签名Bot 自动`                   | 清除固定账号，恢复自动选择；也可填写 `清除`     |
| `#开启音乐签名服务` / `#关闭音乐签名服务` | 保存开关并挂载或卸载服务                        |
| `#音之测测`                               | 用配置中的 `testMusic` 重新签名，回传后发送音卡 |
| `#音之测测 {完整请求JSON}`                | 临时更换测试歌曲或平台，不修改默认测试配置      |
| `#签名音卡 {完整请求JSON}`                | 优先复用精确缓存，再发送音卡到当前会话          |

`Bot` 大小写均可，设置账号也支持 `#设置音乐签名账号 <QQ号>`。`音之测测` 可省略开头的 `#`；失败时会提示生成/回传或当前会话发送阶段的原因。

## HTTP 调用

默认复用云崽 HTTP 服务，签名地址为：

```text
http://127.0.0.1:<云崽端口>/music_card/card
```

向完整地址发送 JSON POST。成功响应直接是音卡 JSON 原文，可作为 JSON 消息发送。请求字段、自定义平台、ID 模式、鉴权和错误码见 [接口文档](docs/api.md)。

先用 GET 访问完整签名地址确认服务状态，再提交歌曲。音卡路径的宿主鉴权失败返回 `401` 和 JSON 错误；请求解析、查询与回传失败同样返回 JSON。

需要单独的本地端口时，将配置中的 `localPort` 改为 `4567` 并重启，签名地址变为 `http://127.0.0.1:4567/music_card/card`。额外服务仅监听 `127.0.0.1`，宿主路由仍保留。

## 配置

用户配置在云崽根目录的 `config/music-card-sign.yaml`；默认配置在插件的 `resources/config/config.yaml`。手动修改用户配置后重启云崽，账号和开关也可通过命令立即设置。

| 字段        | 默认值               | 用途                                                       |
| ----------- | -------------------- | ---------------------------------------------------------- |
| `enabled`   | `true`               | 加载时是否启用服务                                         |
| `botId`     | `""`                 | 固定签名账号；留空时仅在一个 icqq 账号在线时自动选择       |
| `path`      | `/music_card/card`   | 宿主及额外本地服务的签名路由                               |
| `timeoutMs` | `15000`              | 歌曲查询和等待回传的超时，各阶段独立计时，单位毫秒         |
| `localPort` | `0`                  | `0` 复用宿主；非零时额外启动本地端口                       |
| `apiKey`    | `""`                 | 可选插件鉴权，见 [请求鉴权](docs/api.md#请求鉴权)          |
| `platforms` | `{}`                 | 自定义平台名称与应用信息的映射                             |
| `testMusic` | 《晴天》的自定义请求 | `#音之测测` 默认歌曲，可替换完整歌曲字段并指定 `_platform` |

从旧 JS 版升级时，若用户 YAML 尚不存在，会迁移插件中的 `config/config/config.json` 并保留旧文件；已有 YAML 时以 YAML 为准。

### 锅巴配置

已安装 [Guoba-Plugin](https://gitee.com/guoba-yunzai/guoba-plugin) 时，在锅巴的插件配置中选择「本地 icqq 音卡签名」。可编辑上表全部设置；测试歌曲和平台映射使用 JSON 文本框，API Key 使用密码输入框。

点击保存后写入同一份用户 YAML，并立即重新加载音卡服务。平台的 `appsign` / `app_sign` 可为空；Bot 号留空恢复自动选择。参数错误或新端口无法使用时，会提示失败并恢复旧配置和服务。

## 缓存

音卡长期保存在插件的 `data/music-card-cache/`，重启后可继续复用。命中要求签名账号、实际平台信息和完整请求字段全部相同，只忽略 JSON 对象键顺序和 JSON 文本排版。

以下差异会分别缓存，即使生成的音卡看起来相同：

| 请求差异             | 示例                                |
| -------------------- | ----------------------------------- |
| 字符串内部空白       | `title: "晴天"` 与 `title: "晴天 "` |
| 字段是否存在         | 省略 `singer` 与 `singer: ""`       |
| 值类型               | 数字 ID 与字符串 ID                 |
| 地址、平台或扩展信息 | URL 原文、数组顺序和未知字段不同    |

ID 请求命中后会跳过歌曲查询和分享提交。只保存匹配成功的回包，损坏记录会重新签；磁盘读写错误写入日志，保存失败时仍返回本次成功签出的音卡。

删除对应缓存文件可重新签该请求；清空缓存目录可重新签所有请求。也可使用 `#音之测测 {请求JSON}` 绕过旧缓存，成功后更新记录。

## 更新

在云崽根目录执行，然后重启云崽：

```sh
git -C plugins/music-card-sign pull
pnpm --dir plugins/music-card-sign install --ignore-workspace --prod
```

升级时保留用户配置和 `data/music-card-cache/`。手动解压安装的副本无法直接用 Git 更新，可从仓库下载新的 `lib` 分支文件后替换运行文件。

## 常见问题

| 现象                 | 检查方法                                                                            |
| -------------------- | ----------------------------------------------------------------------------------- |
| 加载时缺少依赖       | 在云崽根目录重新执行安装步骤中的 pnpm 命令                                          |
| 找不到在线 icqq 账号 | 确认 ICQQ-Plugin 已接入且账号在线，检查配置的 Bot 号                                |
| 多账号时无法自动选择 | 用 `#设置音乐签名Bot <QQ号>`，或在请求中传入 `self_id`                              |
| 回传超时             | 用 `#音之测测` 检查当前账号；确认歌曲地址可用并查看云崽日志                         |
| 当前会话发送失败     | 检查接收会话的协议是否支持 JSON 卡片                                                |
| HTTP 401             | 检查宿主鉴权及插件 `apiKey`，参见 [请求鉴权](docs/api.md#请求鉴权)                  |
| HTTP 返回 HTML       | 核对请求端口和完整路径，确认新版本已加载；云崽其他路径仍可能重定向                  |
| Cloudflare 524       | 源站响应超时；在运行机器上直接 GET 完整签名地址，再对照 HTTP 入口日志检查代理与服务 |
| 测试指令无响应       | 查看是否有「应用 init 完成」及「音之测测开始」日志，确认主人权限和群聊回复条件      |
| 本地端口被占用       | 修改 `localPort`，或设为 `0` 使用宿主服务                                           |

日志按 `[音卡签名]`、`[音卡指令]`、`[音卡 HTTP]`、`[音卡发送]` 标识阶段，记录启动、账号选择、缓存命中、提交分享、回传匹配和发送结果。失败日志包含阶段和错误详情，HTTP 日志包含响应状态及耗时。

在运行机器上直接访问时使用 `127.0.0.1`；从其他电脑访问则使用服务器地址。直接 GET 正常、域名访问超时时，检查反向代理的目标端口和路径。JiuLi 尚未就绪的请求会返回 `503`，JSON 错误中保留启动阶段。

HTTP、Handler 和命令可以使用不同的生成账号与接收会话。其他插件接入 Handler 或扩展 ID 查询，见 [开发指南](docs/development.md)。
